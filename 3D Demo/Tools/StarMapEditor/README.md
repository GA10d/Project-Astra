# ASTRA 星域编辑器

双击本目录的 `index.html`，用 Edge 或 Chrome 打开。不需要 Python、Unity、安装插件或启动服务器。整个目录应一起保留，HTML 通过旁边的 JS/CSS 文件运行。

左侧选择星域，中间拖动信标，右侧修改名称、坐标、事件和出站航线。按住 Shift 点击起点和目标可以切换一条连线；双击地图空白处新增信标。普通信标需要关联事件并通向出口；入口节点没有事件。坐标范围是 0–1，箭头决定航行方向，位置本身不决定可达性。

“事件库”可配置文字选择与舱内演出。事件可以被多个信标引用，编辑共享事件会影响全部引用者；“复制为独立事件”用于创建变体。演出 1–9 对应游戏里原有的九种演出。观看时间到达后开放选项；演出 3 还要求玩家在舱内完成三处维修。每个事件至少保留一个无消耗选项。

每个选项可分别设置消耗、收益及结算文字。资源定义、起始值、容量、每跳消耗在“航程与资源设置”中修改。0 表示不收取或不发放，负数无效；同一资源同时出现在消耗和收益中时先检查能否支付，再计算收益。达到容量后多余收益舍弃。

## 信标前往按钮文本

选中信标，在右侧填写“前往按钮文本（可选）”，对应节点字段 `travelButtonText`。最多 24 字、不可含换行或控制字符；省略、null、空字符串或纯空格均显示“跃迁至此信标”。字段作用于前往该节点的按钮，不影响抵达后的事件选项，也不改变出口处的“进入下一星域/完成本次航程”。

这是纯显示字段，修改它不改变存档指纹；正在进行的航程仍使用已导入快照，需依既有导入流程启用发布文件的更新。旧配置无需迁移，schemaVersion 仍为 1。旧游戏程序会忽略此新字段并显示默认文本；需更新程序才能显示自定义文字。旧编辑器版本未必保留可选字段，协作时请一起更新 editor.js 与 editor-core.js。

## 信标档案信息说明

节点可选字段 `archiveDescription`，在编辑器“档案信息说明（富文本，可选）”填写，最多 2000 个 UTF-16 字符；为空显示原航路状态。支持换行、`<b>`、`<i>`、`<color=#RRGGBB>`（也支持八位含透明度）、`<size=12>` 至 `<size=28>`，标签必须正确嵌套闭合。不支持 HTML、图片或链接。编辑器提供实时预览，游戏按实际宽度换行、长文滚动。移除抵达前档案中重复的黄色事件标题；事件待处置页面标题保持不变。该显示字段不参与存档指纹，旧配置无需迁移，schemaVersion 仍为 1。变更发布文件仍需在对应星系导入后启用，编辑器与游戏均需更新以使用本功能。

## 导入游戏

1. 处理地图下方的全部配置错误，点击“导出到游戏”，得到 `campaign.json`。
2. 将文件复制到游戏目录中的 `Astra Cabin_Data/StreamingAssets/Navigation/<星系>/campaign.json`，`<星系>` 为 `test`、`zyl` 或 `gzw`。
3. 在游戏 A 墙电脑打开“导航模式”，先选择对应星球，再点击“导入星域配置”，确认校验并导入。
4. 导入成功后当前星系开始新航程，其之前的配置与存档保留备份，其他星系进度不变。导入失败会显示原因，不能带着无效配置继续航行。

Unity 工程使用 `Assets/StreamingAssets/Navigation/<星系>/campaign.json`。test 是现有完整地图，根目录旧 `Navigation/campaign.json` 保留作兼容副本；zyl、gzw 预留目录收到有效的 `schemaVersion: 1` 配置后即可接入，无需修改选择器或航行引擎。运行中的航程使用各星系独立的已导入配置快照，所以替换导出文件后需要进入该星球再次导入。普通重启会继续现有航程。

两位开发者的独立文件范围、存档路径和共享脚本约定见 [星系开发交接](../../Source/galaxy_development.md)。

## 保存、另存为与文件关联

最新版 Edge / Chrome 在支持 File System Access API 的本地页面中可直接写回文件。通过“打开配置”选择并确认载入后，点击“保存”（Ctrl+S）写回该文件；“另存为”（Ctrl+Shift+S）选择另一位置。首次无关联文件时保存会询问位置。每次保存前校验配置，只有写入并关闭文件成功才提示“已写入文件”；失败或取消保留当前修改。

底部显示关联文件名及未保存状态。浏览器自动草稿与文件保存分开：自动草稿不写磁盘；刷新/重开后不保留文件授权关联，保存时需要重新选择位置。拖入文件或普通文件输入导入只能读取，保存时需选位置。重新打开其他文件/载入示例会切换文件关联；撤销/重做同步恢复对应关联。检测到原文件被外部修改时停止覆盖，请另存为再合并。不支持文件写入的浏览器继续使用“导出到游戏”下载。

文件保存不会自动触发游戏导入，也不会更新其他目录的同名文件。选择要编辑的源码/发布配置路径后再保存。

## 草稿与撤销

浏览器会在字段编辑完成后（离开输入框）、拖拽结束时自动保存草稿。撤销/重做最多保留 80 步，在本次页面会话内有效。重新打开工具会恢复本机草稿。若浏览器拒绝本地存储或本机草稿损坏，会在底部显示提示；及时导出文件保留改动。“打开配置”支持重新载入合法 JSON，也可以把 JSON 拖入页面。

校验检查无效引用、重复 ID、环路、死路、不可达节点、未知事件类型、非法资源数量等。它不保证每种资源选择都能通关；燃料或补给用尽可能结束一条路线，需要策划校准收支。

## 示例与测试

`campaign.json` 是三片星域、24 个信标、12 个事件的可导入样例。`default-campaign.js` 是同一份样例的离线入口。两者由工程 `Source/create_navigation_sample.py` 一起生成。

`node test-editor.cjs` 运行编辑器核心的 40 项校验和引用维护测试。游戏侧还会使用自己的 C# 校验器再次检查导入内容。新增代码事件类型须同步扩展游戏处理器、编辑器类型选项和双方校验；仅配置现有类型不需要修改代码。

## 演出 10：泰德野里_未知撞击导致引擎堵塞

编号 10 独立复用撞击、断电、拿锤、三处维修流程，原演出 3 保持不变。需完成三处维修并达到最短观看时长才能结算。修好裂痕后标题为“舱体未完全修复”；白字“三处裂痕已封闭”“主电源恢复”，红字“引擎被未知物质堵塞”。左侧持续警告“引擎堵塞，飞船失去动力”。此警告从进入事件开始，作为本星系本航程的状态，通过航行指令重放恢复，结算/切换其他演出不清除，切到未触发该状态的其他星系不显示，重开航程重置。该状态不额外禁止地图推进；目前没有清除堵塞的交互。数字调试快捷键仍是原 0-9，新演出通过编辑器或代码 TriggerMode(10) 触发。旧程序只支持 1-9，使用 10 需更新游戏与编辑器。zyl“命运的入口”已改为 10，已有航程需重新导入配置。
