# 航程物品与信标条件使用说明

2026-11-06

已加入每颗星球 Campaign 独立的航程物品库存。导航顶部“物品”查看当前数量，“日志”保留原入口。物品不属于通用跨星系背包。现有航程资源系统保持独立。

## 在离线星图工具中配置

打开游戏根目录 Tools/StarMapEditor/index.html，并打开 zyl 的 campaign.json。

1. “航程与资源”中的“物品定义”：添加物品，设置 ID、名称、初始数量、容量；如果来自打印机，选择对应图纸。每种图纸在同一航程最多绑定一种物品。
2. 选中目标信标，在“进入前需持有（不消耗）”填数量，例如密封环填1；为0表示无条件。想进入时直接扣除，则填写“进入时交付（消耗）”。两者都填写时都按进入前库存检查，随后只扣交付数量。
3. 事件处置选项同样支持“需持有（不消耗）”“交付（消耗）”“物品奖励”。物品奖励容量不足会阻止结算，避免关键道具被丢弃；资源奖励仍沿用原有溢出舍弃规则。
4. 保存配置到 UnityProject/Assets/StreamingAssets/Navigation/zyl/campaign.json，在游戏导航中导入更新配置；导入会备份并重开航程。修改 StreamingAssets 不会自动修改旧航程快照。

物品最多64种；ID为1–64位英文、数字、下划线或连字符；名称最多32字；数量为正整数，容量最多1000000。起点不支持入场条件。自动结算的视频会议不支持选项物品门槛，可在其目标信标上设置条件。每个事件仍必须保留至少一个无资源消耗、无物品门槛和交付的备选项，避免事件处置卡死。真正必须持有物品才能继续，请把门槛设在后续信标上。

## 打印机

zyl 已定义密封环 seal_ring、连接法兰 connection_flange、缓冲垫片 buffer_gasket，初始0，容量99，并绑定同名图纸。现有事件文案、选项及航线未设置新的强制门槛；由内容作者明确选择需要哪种部件及哪个信标后配置。

先在导航进入 zyl 的有效未完成航程，再打印并点击“领取已完成部件”；领取将完成品送入本航程物品库存。打印中、完成但未领取均不算已拥有。打印机“累计领取”仍是设备历史统计，不是可交付数量；当前可用数量以导航“物品”为准。旧已领取计数不会补发到新航程。

没有定义航程物品的旧 Campaign 保留旧打印机领取行为。如果 Campaign 定义了物品，领取只处理已绑定图纸的完成品；未绑定的其他部件继续保留在打印机，不阻止已绑定部件入库。若全部完成品都未绑定，提示已完成的部件名称以及应打印的物品/图纸；库存容量不足仍保留本批完成品并提示原因。

领取先保存批次凭据，再写入航程存档，最后清除完成品。同一批次重试只会到账一次。保存失败请重试；如果已经切换星系，回到原航程完成领取。如果原航程已被重开或导入覆盖，按住 Shift 点击“领取”可明确丢弃旧待领取批次，然后重新打印；这会删除该批次完成品，不会转赠给新航程，也不会撤销旧航程已经到账的物品。

路线只能单向前进。必须在门槛之前提供物品获取机会，或者让玩家能留在当前信标使用舱内打印机，不要设计必须回头才能获得的关键道具。

## JSON 对应字段

Campaign 的 items 示例：
```json
"items": [
  {"id":"seal_ring","name":"密封环","initial":0,"capacity":99,"fabricatorBlueprint":"seal_ring"}
]
```
信标或选项检查持有：
```json
"requiredItems": [{"itemId":"seal_ring","amount":1}]
```
信标或选项消耗：
```json
"itemCosts": [{"itemId":"seal_ring","amount":1}]
```
选项奖励：
```json
"itemRewards": [{"itemId":"seal_ring","amount":1}]
```
fabricatorBlueprint 可用 seal_ring / connection_flange / buffer_gasket，留空代表不从打印机获得。以上字段可省略或为空数组。
