# zyl 黑幕与 Unity 导航调试工具

更新：2026-11-05。本次更新源码，未构建；现有 Build 不包含本次修改。

## 导航调试工具

1. 在 Unity 中打开已有玩家船的舱室场景，例如 `Assets/Astra/Scenes/Cabin04.unity`。若新菜单未出现，先刷新项目、等待脚本编译完成。
2. 在**未进入 Play**时打开菜单 **Astra → Zyl 星域导航调试**。
3. 选择“起始信标”和“前置路线”。路线下方会列出完整途经信标。
4. 点击“从选中信标开始”。工具自动进入隔离 Play，跳过前面的演出与确认，从目标信标的事件入口开始正常交互。
5. Play 中可以重新选择目标与路线再启动，或点击“重播当前事件”。重播会撤回当前事件的完成、结算与资源变化，保留之前的实际路线；演出参数会在重启演出时重新读取。
6. 停止 Play 即退出本次隔离会话。之后普通 Play 继续使用原来的正式存档。

若已经通过普通播放按钮进入 Play，请先停止，再从本窗口启动。工具不会把正在运行的正式航程强行切换到调试存档。

“进入星系”本身没有事件，选它会显示导航起点；没有事件的信标不能使用“重播当前事件”。文字选择事件可以重播。导航调试窗口只在 Unity 编辑器出现，不会进入打包游戏。

### 前置路线如何恢复

- 使用当前真实 campaign 和导航引擎重放指令，不把演出类型临时替换成 choice，也不直接改当前信标字段。
- 前置演出记为完成；前置选项优先选择第一个无消耗选项，否则使用第一个可支付选项。资源不足则报错，不凭空补资源。
- 引擎堵塞按原导航记录恢复。已穿越传送门且尚未进入胃内时恢复传送门抵达外景；从“胃中囚徒”起步会先恢复胃内环境。
- 从胃内跳回前面的信标或重播米霍尔事件，会先等待旧环境卸载，再启动目标事件。
- 当前星图可选择米霍尔事件的四种前置分支组合。未来节点会随“重新读取星图”更新。前置出现 performance 会议时，需要明确结局，本工具会报错，不伪造结局。
- “重播当前事件”沿当前调试航程实际记录回退，不使用窗口中尚未执行的另一条路线。

### 隔离存储

每次从编辑状态启动调试，会创建工程内 `Library/ZylNavigationDebug/runs/<时间与随机ID>/`。导航配置快照、航程及电脑便签均写入此处；窗口显示实际目录。正式星图、正式航程及正式电脑数据不作为调试写入目标。历史调试目录保留用于排查，不作为交付源码。

## 全屏黑幕

巨兽达到加载距离后，由独立 `ZylScreenCurtain` 组件绘制屏幕实际尺寸的黑幕，拥有固定的最前绘制层，和邀请提示、电脑界面分离。全黑阶段电脑、舱室HUD、演出提示与暂停菜单暂不绘制，避免漏出；淡入阶段恢复在黑幕下绘制。黑幕期间屏蔽舱室、电脑、调试快捷键与底层鼠标/键盘输入。

只有确认全黑帧已绘制，下一帧才允许开始加载。加载完成后仍按现有顺序关闭通话和电脑、朝向舷窗墙面，再淡入。环境恢复也使用同一黑幕，避免两个遮罩叠加改变淡入透明度。加载失败时黑幕自身显示错误与重试。

# 星域调试库存

2026-11-07，新增到现有 Unity 菜单 **Astra > Zyl 星域导航调试**；无需另开工具。

## 启动前配置

1. 停止普通Play，打开 Cabin04 或已有玩家船的场景，再打开该窗口。
2. 选择起始信标和前置路线，展开下方 **调试库存**。
3. 为每种已定义物品填写本次调试的携带数量（0至容量），也可用＋1/－1、恢复物品初始数量、清空库存。
4. **补齐选中信标所需物品**：补到能支付该信标入场消耗、并满足后续各选项物品需求的数量。若合计超过容量，会明确提示；可改用自动补齐，抵达后再补选项。
5. 点击上方 **从选中信标开始**。使用独立的 Library/ZylNavigationDebug/runs/<本次目录>，不改正式航程。

初始数量用于航程起点；重放前置路线时仍按游戏规则消耗物品、领取选项奖励，因此抵达目标后的持有量可能不同。重播当前事件时，窗口指定数量会应用在该事件入场之前，入场消耗仍正常扣除。

默认勾选 **启动/重播时，自动补齐沿途与目标的物品门槛**：在前置路线每次入场/必要结算前按缺口补给；到达目标后补齐各选项所需物品。仅启动或重播时执行，运行中不会持续补回被清空的物品。前置事件仍优先选择可结算的无消耗选项，不伪造performance会议结局，也不补普通航行资源或跳过资源不足。

## 运行中管理

在同一窗口展开调试库存，每行显示名称、ID、当前持有量与容量。

- 输入数量后点 **设置**，只修改该物品；＋1/－1根据当前实时持有量立即调整。
- **应用全部数量** 提交所有输入；**清空库存** 立即清空本次隔离航程的物品。
- **读取当前数量** 用真实库存刷新输入框，方便查看消耗或领取后的结果。
- **补齐当前事件选项** 只增加不足部分，不降低已有数量。
- **补齐选中信标所需物品** 会考虑目标入场消耗；如果当前已在该信标，则不重复预留已经扣过的入场消耗。

准备测试缺物品分支时，可取消自动补齐，从前一个信标开始并清空库存，再手动前往目标；或在当前事件清空物品，验证相关选项重新受门槛限制。入场门槛只在前往时检查，不会因事后清空而倒退当前位置。

只列出航程已定义的物品，不添加物品定义、不改initial/capacity，不修改打印机生产队列、成品或图纸绑定。没有绑定打印图纸的剧情物品同样可调试。运行中的定义来自当前隔离航程快照；源星图已更新时，重新从选中信标开始载入新快照。

## 隔离与重放

普通Play、非zyl航程、同步环境期间均禁用写入。库存设置使用仅Unity Editor支持的 `zylDebugInventory` 指令，校验已定义ID、去重、0至容量后，原子提交到当前隔离航程。减少/清空同样可被命令重放；相同数量不追加指令，计时状态和普通资源保持。

NavigationSession对每条调试库存指令复核存档规范路径及启用的调试根目录。即使把调试存档误放进普通目录，也会拒绝载入并保留文件。Player构建不包含此命令、窗口、规划或写入接口。现有正式存档格式不变。

窗口库存输入、自动补齐开关和目标选择支持编辑器序列化；同一次隔离运行中的航程重载会从命令恢复库存。停止后再次从窗口启动仍创建新运行目录，旧调试记录保留在Library下供查看。

## 验证与交付

运行时/排除UNITY_EDITOR与完整编辑器两路源码编译通过；隔离Unity 62项检查通过，零日志错误。覆盖真实zyl中16条含物品门槛或通往我们仨的路线、未绑定物品、零值/容量/重复/无效输入、批量失败不部分改动、真实门槛、重播、存档重载、非空倒计时快照保留、普通Play拒绝、目录越界/伪前缀拒绝，以及窗口方法和序列化。

正式导航/电脑存档前后哈希一致。UI在隔离编辑器中创建和重绘，未进行真实鼠标或截图视觉验收；未操作用户正式航程，未构建exe。代码和报告位于管理目录 output/debug-inventory，修改前备份在backup。
